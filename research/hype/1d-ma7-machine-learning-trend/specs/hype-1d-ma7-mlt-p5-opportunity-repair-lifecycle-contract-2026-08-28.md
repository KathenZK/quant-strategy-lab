# HYPE 1D MA7 MLT P5 机会修复与生命周期策略训练合同

## 1. 研究问题

P5 是一个全新的诊断实验，不修改 P4，也不修改冻结的 `HYPE-1D-MA7-ABT-V7.1`。它不再只学习 V7.1 已有交易的去留，而是回答一个更完整的问题：一次原始 MA7 穿越发生后，当前方向是否已经进入值得持有的稳定趋势状态。

模型每天只输出一个概率，再由冻结状态机转换为四类动作：补入、继续持有、退出、直接反手。目标是修复 P4 无法处理的三个结构性缺口：V7.1 没入场时没有候选、固定三日延长无法长拿、动作空间没有双向反手。

## 2. 数据隔离

- 训练期固定为前 365 个日决策：`2025-05-31 00:00 UTC` 至 `2026-05-30 00:00 UTC`；训练终点开盘为 `2026-05-31 00:00 UTC`。
- 后 81 日固定为验证期：`2026-05-31 00:00 UTC` 至 `2026-08-20 00:00 UTC`。
- `develop` 必须调用物理截断的 365 日上下文；小时线与资金费率的读取终点都不得晚于训练终点。
- 标签需要未来路径，因此训练期最后 3 个无法成熟的日样本必须删除。
- 开发阶段不得加载、统计、画图或查看后 81 日。只有开发门禁通过并生成带哈希的 manifest 后，独立 `validate` 阶段才允许一次性读取验证期。
- 后 81 日只用于评价冻结模型；不得据其结果修改特征、模型、阈值或状态机。由于 P0-P4 已经看过同一窗口，本轮仍标记为 `reused holdout`，不是干净 OOS。

## 3. 监督标签

标签只在训练期内部构造，未来信息只能进入 `y`，不能进入特征 `X`。

1. 使用既有 hindsight trend lifecycle 引擎生成逐日原始趋势标签。
2. 使用既有三状态稳定化程序：7 日中心回归趋势强度、`abs(beta7/ATR7) >= 0.08`、`R² >= 0.35`、Viterbi 转移惩罚 `2.0`，并清理短于 3 日的非零片段。
3. 原始 MA7 上穿把当前 root 方向设为 `+1`，下穿设为 `-1`；后续反向穿越会替换 root。
4. 当日稳定趋势方向与当前 root 方向相同，目标 `trend_active=1`；其余为 `0`。

这是一种事后监督标签，只负责教模型识别趋势生命周期。它绝不能作为实时输入，也不能被描述为可直接交易的确定真相。

## 4. 因果特征块

所有滚动量只使用当日收盘及更早数据；动作最早在下一日开盘执行。

### B1：穿越根与成熟路径

- root 方向、root 年龄、当日与首次穿越的 MA7 距离/ATR、距离变化；
- MA7 的 1/2/3 日斜率和斜率加速度，全部按 root 方向对齐；
- 1/3/7 日方向收益、K 线实体、收盘位置、振幅、RSI6、ER7；
- 最近 3/7 日位于 root 同侧的比例、距离单调扩张比例、7/14 日穿越次数。

### B2：穿越前市场结构（在 B1 上累加）

- 14/30 日方向收益、MA7-MA30 距离、MA30 七日斜率；
- 30 日区间位置、距 30 日高低点、30 日回撤与反弹；
- ATR、振幅和收益波动的 7/30 日压缩比。

### B3：参与度与资金费率（在 B2 上累加）

- 日成交量 7/30 日 z-score、7 日方向成交压力；
- 当日、3 日、7 日资金费率累计及三日变化。

特征块按累加顺序比较。若 OOF AUC 相差不超过 `0.01`，选择更小的特征块；否则选择 AUC 最高者。

## 5. 模型与开发切分

- 模型固定为 `ExtraTreesClassifier`：600 棵树、`max_depth=6`、`min_samples_leaf=6`、`max_features=0.75`、`class_weight=balanced`、随机种子 `20260828`。
- 开发选择区为训练期前 285 日。
- 固定扩展窗 OOF：`[120,160)`、`[160,200)`、`[200,240)`、`[240,285)`；每折训练集在测试起点前额外 purge 3 日。
- 特征块仅依据开发区 OOF AUC 选择。
- 内部确认区固定为训练期第 286 至 365 日；模型只用前 285 日的成熟标签拟合一次，在内部确认区不重训、不调参。
- 开发门禁同时要求：开发 OOF AUC `>=0.55`、内部确认 AUC `>=0.55`、内部确认净收益非负，并且 P5 对稳定趋势的按天加权同向覆盖率严格高于同期 V7.1。

## 6. 冻结交易状态机

- 概率使用因果 EMA，`alpha=0.50`。
- 空仓时，若当前 root 非零且平滑概率 `>=0.55`，下一日开盘按 root 方向以 1.0x 入场。
- 持仓且 root 未反向时，概率 `>=0.45` 继续持有；低于 `0.45` 则下一日开盘退出。
- root 反向时，先退出原仓；若新方向概率 `>=0.55` 且较原方向持有阈值至少高 `0.05`，同一开盘直接反手，否则只平仓。
- 同一 root 在概率重新成熟后允许再次入场；退出后至少等待一个完整日决策，防止同日抖动。
- 不设固定止盈，不设 30 日最大持有；终点强制平仓。

P5 当前没有复刻 V7.1 的小时级保护止损，因此无论结果如何都只能是教学/诊断模型，状态固定为 `not promoted / not live-ready`。

## 7. 回放与比较

- P5 与 V7.1 均使用 1.0x、Binance 每次成交手续费 `0.001`、不利滑点 `4 bps/fill`、实际资金费率和 1 小时顺序回放。
- 必须分别汇报：训练期全量重拟合表现、开发 OOF、内部确认、后 81 日验证（仅门禁通过后）、交易数、方向数、胜率、PF、1h MDD、成本、资金费率和稳定趋势覆盖。
- 训练期全量表现是 resubstitution，只说明拟合能力，不代表泛化能力。
- 默认补充 `1d/7d/1m/3m/6m/1y` 可用分片；不足窗口按实际可用天数标记。
- 本轮是普通诊断实验，默认不生成新的交易路径 HTML；若结果值得逐笔复盘，再单独生成 P5/V7.1 对照图。

## 8. 结论状态

- 开发门禁失败：`DEVELOPMENT_FAILED_HOLDOUT_LOCKED`，禁止读取验证期。
- 门禁通过但验证期未同时提高净收益与趋势覆盖：`V7_1_NOT_BEATEN`。
- 验证期同时提高净收益与趋势覆盖，且 MDD 不比 V7.1 恶化超过 2 个百分点：`EDUCATIONAL_REUSED_HOLDOUT_WIN`。
- 所有状态都保留 `diagnostic-only / reused-holdout / not promoted / not live-ready`。
